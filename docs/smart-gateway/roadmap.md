# 智能网关与 UI 优化路线图

## 目标与范围

统一供应商（Schema 34）之后，优先消除「配置已填但请求不按配置执行」和「界面正常但上游不可用」的问题，再完善运行可观测性与页面结构。参考 magpie 的可解释路由与配置漂移、cc-switch 的三态熔断、ai-toolbox 的分类健康状态；不直接搬入样例代码。

### 第一批：正确性与可靠性（已实现，持续回归）

- 模式显式备用不再依赖档案 `fallback_mode=model_chain`；备用目录 ID 解析到实际供应商和模型，保留 allowlist 与显式 pin。
- Code/Codex 共用失败分类与出站健康门禁；上游级 Auth/Quota/RateLimit/Transient、模型级 ModelUnsupported，半开仅放行一个请求。
- 401/403 不显示正常；探测目录缺失仅表示可达未知，不能清除真实请求触发的熔断。
- 默认重试码移除 400–404，不覆盖已有用户设置；明确模型不存在可走显式备用；保留协议兼容修复，不将所有 400 当成可重试。
- 档案备用控制、模式保存错误反馈、连接状态与端口、概览数量、健康详情。
- 第一批不升级 Schema；第二批已增加 Schema 35 尝试链列。所有测试继续隔离，不改安装版或真实 Agent 配置。

### 第二批：可解释性与日志（已实现，验收中）

1. 试跑复用实际计划构造和健康快照，显示预算/冷却/allowlist 导致的跳过与全部候选；试跑不得占用半开 permit 或产生出网。
2. 请求明细记录实际尝试的供应商、模型、耗时、失败分类与最终结果。沿用 correlation/hop 去重，不能把每次尝试当成新的用量。
3. Schema 35 新增 `proxy_request_logs.attempts_json`，不新建每次尝试的用量行；旧记录无该字段时正常显示，详情安全解析实际尝试链。

验收：相同配置及健康快照下，试跑与实际首选/备用顺序一致；界面能解释「为什么切换」；Key、请求正文及敏感错误内容不进入诊断字段。

### 第三批：UI 信息架构（已实现主体，验收中）

- 保留七项主导航与现有顶栏/侧栏偏好，不重做应用外壳。
- 供应商页作为唯一 Agent 连接编辑入口；网关页的重复绑定表改为只读摘要和跳转。
- 网关智能分区收敛为服务、路由、请求日志；反代网关保持独立。
- 概览展示 Agent → 连接方式 → 网关/上游状态及最近结果，区分「配置已连接」「网关运行中」「最近请求成功」，不要互相代替。
- 请求日志已提供后端全局 Agent/模式/状态/关键词筛选、错误突出与尝试详情；复用 `usage-log-recorded` 合并刷新，保留 10 秒兜底查询，自动刷新关闭时同时停用两者。
- 上游健康、当日成功率与分币种成本，批量测试限制并发并可取消。
- 配置漂移：复用现有 ownership 快照，预览差异后由用户重新应用；禁止后台擅自改回 live。
- 托盘按 Agent 提供快捷连接操作，复用已有 IPC 与确认边界；Desktop/DSH 保持产品面隐藏。
- 统一交互规范写入 `docs/DESIGN.md`；按职责拆分 GatewayPage/GatewayUpstreamPanel，不为行数机械拆文件。

验收：绑定入口唯一；页面反映真实连接状态；路由编辑不夺取 direct/官方连接；两个布局与深浅色可用；中英文齐全；弹窗使用 App 级 Modal。

### 第四批：可选增强（实施与验收中）

- 已接入按实际上游共享的固定 RPM、并发、有界 FIFO 队列；准入先预留，健康门禁通过后提交出站计数。配置保存于本地资料库，不修改 Agent live。
- 入口与出站许可跟随响应体释放；流式响应体取消异步写 `cancelled`，已记录协议终态不被覆盖。响应头前取消日志带上供应商、路由和尝试链。
- 首个有效输出截止默认关闭；启用后在客户端提交前预读，支持文本、思考、工具与正常空完成，保留有界原始字节回放。不将响应头或 ping 当成输出。Anthropic 与 Chat 超时、缓冲超限会在提交前走已有备用；响应头交给客户端后不再切换。
- 请求日志、当日统计与拓扑已接共享事件刷新和尾随补查；仅新日志或终态变化触发短动画，reduced-motion 关闭动画。
- 子代理上游继承默认关闭。可选头 `x-cs-parent-session-id` 只在已识别子代理上生效，不猜测父会话，不转发出网；显式目录和规则锁定不被覆盖。尝试链记录 `queueWaitMs`。
- 尚未完成：完整视觉/键盘验收，以及真实 AG/Kiro/供应商出网联调。截图不能代替读图验收。
- 首输出超时可能仍产生供应商费用或远程工具副作用，丢弃响应不等于撤销远端执行。

## 可靠性边界

- AG 429/504：智能网关显式备用链允许；通用跨供应商策略仍受原有反代保护。Kiro 429/504 不跨供应商。
- 所有候选处于硬冷却时，不以 restLast 绕过认证/额度/Retry-After；返回可重试响应与等待时间。到期后半开单探测。
- 仅默认指数退避封顶五分钟，服务器提供的较长 Retry-After 不截短。
- 重试阶段尚未提交 SSE 响应；本轮不提前发送 keepalive，以免承诺 200 后不能返回真实 HTTP 错误。排队保活留到独立流生命周期设计。
- 中途断流沿用完整帧转发与正常助手错误收尾，公开 `message.model` 回显不变。

## 验证门槛

每批独立验证并记录结果：L0、隔离 L1、Clippy、前端 lint/build；类型变化按 ts-rs/手写类型实际归属同步。涉及 live 写出/绑定时增加 L2 与 DOM 验证。真实 AG/Kiro/供应商联调需单独记录，不用 mock 通过代替。

前三批验收基线：946 项 Rust 测试及 11 项 L2 通过，不能替代第四批修改后的回归。第四批已通过上游准入、首输出预读与 Anthropic/Chat 备用、响应头前取消日志、父会话上游继承、非流式信封准入和事件 Hook 源码测试。全量 `cargo test --lib -- --test-threads=1`：982 通过，18 失败，失败全部是 Windows 凭据库 error code 8（含 1 项 `test_existing_upstream_with_key_hit` 与 17 项 `system_test`），不是本次路由或生命周期改动。完整视觉/键盘验收和真实 AG/Kiro/供应商出网仍未完成。

不纳入：模型组负载均衡、JS 分类器/路由脚本、局域网监听、响应缓存。本轮不发版、不提交、不自动安装。
